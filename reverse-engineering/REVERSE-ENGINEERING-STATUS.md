# Dungeon Raid 可继续开发版本：逆向盘点与输入恢复

日期：2026-10-17。原版：1.3.4。目标：掌握可修改源码，保留原版玩法，支持现代手机全屏、高清素材、多语言和可扩展教程。

## 最新进展：整条路径、攻击与奖励已接通

新增 path 接入模块，统一 Selection / Round / Battle 之间重叠字段的归属；将 MatchTiles、AttackSkull、实际消除、奖励初始化与移动、到达入账连接在同一持久棋盘上。当前 16 个模块、46 个具名恢复流程，ProcessInput / Game::Process 部分分支另列。新接入适配器不冒充多恢复一个原函数。

源码独立演示已经做到：周边八格加圈内一格全部消除，9 个奖励在 25 帧内到达，金币 0 → 18，额外一帧不重复入账。没有界面，目标坐标由演示接口提供。当前停在下落补位边界。

本次联合对照通过 517 个路径场景、26 个输入手势（含 6 个敌人路径）、973 个操作/帧步骤及 412 个实际到达奖励。完整证据见 `PATH-INTEGRATION.md`；消除、队列、资源入账、运动及奖励主循环子段的隔离证据见 `MATCH-REWARDS-RECOVERY.md`。16 模块通过 macOS 双架构及 iPhone ARM64 编译，仍不是可玩 App 或 IPA。

下落补位、生成、敌人阶段、回合收尾、完整主循环与输入门槛尚需恢复。全屏、HD、中文、多语言与教程尚未实现。

## 前一阶段：符文围合与松手前置处理

此前恢复了符文围合扫描、圈内计数、高亮请求和松手前置处理。当时 MatchTile 只记录请求；本次已在新的联合验证及 rewards_demo 中连接实际实现。符文独立阶段证据见 `RUNE-RECOVERY.md`，其中范围描述保留历史含义。

## 前一阶段：输入分支与资源预览

在下述盘点和随机函数恢复的基础上，新增两个 C++ 模块：`recovered_stroke` 和 `recovered_preview`。目前共 10 个模块、39 个具名恢复流程，加上 `ProcessInput` 的部分分支；后者没有冒充完整函数，也不计算完成百分比。

- 起笔、连续连线、回退、取消：629 个手势场景、1,781 个操作步骤与原始指令对照一致。
- 松手分支判断：270 例一致，只判断普通清理、提交路径、职业卷轴三个去向，不执行这些分支的后续效果。
- 资源预览：1,192 组独立计算一致；接入连续手势后，623 个场景、1,727 步一致。两个手势测试集重叠，不能相加当独立覆盖量。
- 10 个模块已编译通过 macOS 双架构和 iPhone ARM64 构建。源码独立编译的命令行示例能走完三格金币连线、预览、提交分支判断和取消，无需执行原游戏程序。

这些结果证明部分规则已成为可编辑、可编译的新源码。尚未证明完整游戏可玩、真实 UIKit 触摸正常或手机全屏界面完成。详细边界、命令及源码入口见 `INPUT-RECOVERY.md`。

## 前一阶段交付与结论（保留历史范围）

已直接检查现有源码、验证脚本、原始汇编与资源，而非沿用之前的口头进度。

- 确认此前已有 **7 个 C++ 模块、33 个恢复流程**；逐项核对的原始代码字节哈希全部匹配。历史测试报告仍是函数级/场景级证据，不是完整游戏验收，本轮没有重复跑这些旧测试。
- 新增 **5 个随机数函数的源码恢复**，实际执行原 ARMv7 代码，与原生 ARM64 实现比较返回结果和种子状态，通过。现在有 8 个模块、38 个恢复流程；这不是完成比例。
- 从 14 张具名数据表提取 **246 条文本记录**，每条保留原始地址、表名、索引和稳定键。没有翻译，也没有假称这些覆盖全部游戏文字。
- 明确完整回合缺口：输入调度、单格消除、奖励事件与入账、下落补位、生成数值、敌人行动、回合结束。只补两个函数不足以形成原版完整回合。
- 全屏、高清素材、中文显示、新教程及新的可玩 iOS 界面，本轮均尚未实现。现有手机兼容版依旧不是这份恢复源码构建出的完整游戏。

| recovered_round.cpp | 1 | MatchTiles 路径遍历、伤害/攻击调度、交叉与边缘判定 | MatchTile 与 MoveMatchedTiles 只发事件，没有对应完整实现 |
| recovered_progression.cpp | 11 | 职业校验、编码/解码、升级、成就相关流程 | 游戏局面存档、文件写入、队列时序未实现 |

### 本轮新增：recovered_random.cpp

| 原函数 | 原地址 | 恢复内容 |
|---|---|---|
| SetRandSeed | 0x1b6c0 | 6 个随机流独立设置；编号 6 设置全部；无效编号不改变状态 |
| FlushRandSeeds | 0x1b6ec | 推进全部 6 个随机种子 |
| GetRandSeed | 0x1b724 | 查询种子；无效编号返回 0 |
| RandUnitF | 0x1b76c | 32 位乘法回绕、位构造浮点数、原运算顺序 |
| RandI | 0x1bca0 | 上下界可倒置，保留原 float32 运算和取整顺序 |

关键细节：虽然乘数为 16807，原版并不是常见的模 2³¹−1 算法。直接套用标准随机库会改变补位、掉落和后续游戏状态。实现保留了原版的 32 位回绕运算。

本轮实跑 `verify_random.py`：设置种子 90 项、查询 90 项、全流推进 64 步、单位浮点序列 1,568 步、整数随机数 5,742 步。原函数和原 Clamp 指令均真实执行；只适配平台库 `floorf`。逐步比较全部种子及结果，不只检查结果是否在范围内。

验证范围：合法随机流 0–5，整数范围样本在 ±1,000,000 内，包含正负数、倒置边界、相同边界、零种子及连续调用。未声称极端溢出输入、启动取种策略、浮点范围 Rand、完整棋盘或完整游戏已验证。新随机模块尚未接入生成逻辑；旧测试中的随机适配器也没有偷偷替换。

## 完整回合的真实缺口

以下是静态指令查证；调用点证明依赖存在，不表示每个分支都会执行，也不表示整个状态机已恢复。

| 环节 | 原入口 | 查证到的事实 | 下一项恢复内容 |
|---|---|---|---|
| 新局初始化 | InitNewGame 0x15c50 | 有完整原函数，当前无对应恢复模块 | 起始玩家数值、棋盘、随机种子使用与职业配置 |
| 输入调度 | ProcessInput 0x16638 | 起笔、连续连线、取消、符文预览重置、松手前置处理与路线判断已恢复；原入口测试预先满足输入门槛 | 输入阻塞/阶段门槛、特殊模式处理、实际路径结算和后续阶段 |
| 路径提交 | MatchTiles 0x12188 | 已接实际攻击、消除及奖励，结束时发 MoveMatchedTiles 事件 | 恢复补位实现和周边主循环 |
| 单格消除 | MatchTile 0xbe60 | 已恢复并接入符文；实际 AddToken 可接入 | 接完整路径；SetSpecialType、Shapeshift 等子系统 |
| 奖励事件 | AddToken 0x9890、Token::Process 0x21644 | 已恢复初始化、移动与到达；主循环奖励子段已对照 | 特殊目标选择、真正 UI 目标与其余主循环 |
| 资源入账 | AddResource 0x12ee8 | 已恢复资源数值变化，奖励到达后实际入账 | Healing、CheckEndGame、菜单及 UI 子系统 |
| 下落补位 | MoveMatchedTiles 0x10ed8 | 按列、从底向上扫描；找上方未消除棋子，否则生成新棋子；另有特殊敌人 Stab 调用 | 棋子身份/状态交换、生成顺序、特殊敌人分支 |
| 补位生成 | RandomiseTile 0xf5b8、Tile::SetType 0x3f32c、GenerateStats 0x3e740 | 有职业/难度/敌人/特殊棋子依赖，不能用等概率随机替代 | 类型权重、属性数值、随机流与调用次序 |
| 敌人行动 | ProcessAttack 0x14118 | 被主循环 0x17cdc 调用，含反击、伤害、再次补位等分支 | 阶段转换及玩家/敌人的数值结算 |
| 回合收尾 | EndOfTurn 0x13574 | 输入调度在阶段值 8 时调用；包含毒伤、冻结、敌人能力、再次补位与存档 | 持续效果、回合数、结束检查与可再次输入时机 |

因此不能将“消除→奖励→敌人→补位”画成已经证实的单一顺序。原程序允许多个阶段触发补位，奖励和动画完成状态会影响后续调度。

原函数片段保存在 `evidence/`；`static-call-sites.json` 记录直接具名调用点，排除间接调用，不能当完整控制流图使用。

## 全屏、高清、多语言的具体依据

### 全屏

现有输入恢复代码明确包含 `y * 1.5f`、棋盘上边界 `0.246875f`、6×6 棋盘等旧坐标约定。这解释了为什么只扩大窗口不足以可靠适配现代屏幕，但不是对当前黑边原因的完整诊断。

新工程应把屏幕布局和游戏规则坐标分开：屏幕负责安全区域、棋盘方形区域、顶部数值和底部技能；触摸先转换为统一棋盘坐标。旧规则函数中的坐标假设需通过适配或有证据的重构处理，不能直接把乘数改掉后继续宣称行为一致。

### 高清资源

已核对解码图片：tiles.png / icons.png 为 1024×1024 图集，menus.png 为 512×512，3 张字体图集均为 128×128，启动图为 320×480。图集尺寸不等于单个棋子的分辨率，也不意味着已经高清化。

下一步建立“游戏对象→图集区域→独立素材键”的映射，先替换一组棋子验证渲染与触摸。尚未制作或修改美术素材。

### 多语言

`localization-source.json` 包含技能名/说明各 40 条，敌人名/说明各 33 条，以及职业、种族、天赋、缺陷、种族加成和解锁说明等 10 张各 10 条的表。总计 246 条记录；部分名称可能为占位或特殊类型，不假定都直接展示给玩家。

提取时逐项检查：getter 的 PC 相对地址与符号表一致、固定记录宽度符合指令、每条字符串在自身记录内终止并可解码。中文字段保留 null，避免把未经审阅的猜译写进资源。

3 个旧字体文件实际包含 95、32、48 个字形，最大字符编号不超过 126，没有中文字形。因此汉化需要 Unicode 字体和排版支持；仅替换英文字符串无法完成。菜单、帮助、开场文字、动态格式串和图片内文字尚未完整清点。

## 下一阶段开发顺序与验收

1. 起笔、延伸、取消、符文、松手前置处理和整条路径已通过 path 适配器接通；共享字段归属已明确，继续补输入阶段门槛和完整主循环。
2. MatchTile、奖励事件和 AddResource 已在整条路径场景接通；继续恢复 MoveMatchedTiles 与生成依赖。新随机模块用于确定性对照；允许替换的是表现接口，不能把未恢复的数值行为当成空事件。
3. 恢复敌人阶段与 EndOfTurn，用同一棋盘、职业状态和种子连续执行若干回合，比较逐阶段状态。明确列出未支持的特殊敌人/技能，不静默替代。
4. 在此基础上接现代 iOS 全屏主界面、中英文资源和高清棋子样例。显示层可以独立推进，但未接真实规则的画面只能标为界面原型。

第一个可玩阶段的验收：用自己的源码完成起笔、连线、松手、消除、奖励入账、敌人行动和补位；能开始下一回合；可修改图、文本和规则；核心回合不执行旧游戏二进制。

本轮不交付新 IPA，不把兼容运行层的编译或安装测试当作原生重建进度。

## 复现与文件导航

在包根目录可用：

```sh
python3 reverse-engineering/audit.py --reference reference
sh recovered/build.sh
python3 recovered/verify_random.py
```

构建需要已安装 Xcode/SDK。随机对照使用随检查点保留的本机 ARM64 TCI 运行依赖；它只用于验证原始指令，不是未来 iOS 游戏运行所需依赖。安装包、开发者证书、签名与手机连接不在此复现流程内。

- `inventory.json`：逐个恢复流程与历史验证边界。
- `assets.json`：图片尺寸、哈希和字体字形统计。
- `localization-source.json`：可用于多语言开发的原版文本表。
- `static-call-sites.json`、`evidence/`：原始调用点与待恢复函数证据。
- `../recovered/random_provenance.json`、`random_verification.json`：本轮新增逻辑来源和实跑结果。
- `../recovered/README.md`：早期阶段记录，其中“33 个流程”等时间性描述以本报告为准。

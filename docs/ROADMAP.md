## 一、项目目标（用户确认）

4. 新技能、新职业等新内容放到最后。

## 二、技术路线图（整体怎么搭）

```
 原版老程序（只有成品，没有图纸）
        │  ① 读懂：把机器码翻成可读指令，逐段分析
        │  ② 对照：在模拟器里运行原版片段，得到"标准答案"
        ▼
 规则核心（"大脑"，C++）          ← 现在主要在这一层
   战斗、敌人、奖励、回合、新局、技能、装备、菜单规则……
   每一块都与原版逐步比对，必须完全一致
        │  ③ 会话接口：前端每帧把手指位置交给大脑，大脑交回要显示的内容
        ▼
 界面层（"前端"，Godot 引擎）
   画面、动画、音效、触摸、菜单、多语言、教程
        │  ④ 一套项目导出到各平台
        ▼
 iPhone / iPad（优先） → 安卓 → Windows / Mac（→ 网页，可选）
```

| 层 | 用什么 | 现状 |
| --- | --- | --- |
| 读懂原版 | 反汇编、Unicorn 模拟器（运行原版片段） | 持续使用 |
| 规则核心 | C++（recovered/，24 个模块） | 约八成；整局已能从新开局打到结束，与原版逐帧一致 |

## 六、主要风险

1. **版权（最大风险）**：《Dungeon Raid》的名称、美术、音效和原程序属于原作者 / 版权方（原开发商 Firemint，后被 EA 收购）。我们写的是新代码，但规则是从原程序读出来的。自己玩、内部研究，和公开上架是两回事：公开发布前通常需要取得授权，或者改用自己的名称和全新美术。不同国家规定不同，**建议上架前咨询专业律师**（我不是律师，这里只是提示风险）。这件事决定 M6 能否进行，不影响 M1～M5 的开发。
2. **美术**：高清画面需要新美术，是时间和成本最不确定的部分。
3. **原版规则还剩约两成未还原**：技能、装备、菜单规则都比较大，估算可能偏差。按小块推进、每块验证，可以随时看到真实进度。
4. **AI 额度**：额度用完会停，换工具接手要几分钟；进度都存在项目文件里，不会丢。
5. **部分少见情况测试不到**：有些规则在随机对局里很少出现（记录在 VALIDATION.md），后续会专门造情景补测。

给接手的 AI：用户不是开发者。汇报用通俗中文，先说结论和进度，少用术语；用到术语时用类比解释（如"大脑 / 前端"）。用户负责选择由哪个 AI 工作、试玩和决定画面手感；代码、测试、记录、交接由 AI 完成。确定下来的决定写入 docs/DECISIONS.md，本文件记录对话里的问题和给用户的说明，按日期追加。

## 2026-10-20（Claude）

### 用户问：这几天做了什么？

用通俗说法向用户说明的内容：

- 项目是把老 iPhone 游戏《Dungeon Raid》重做一遍，让它在现在的设备上运行，规则与原版一模一样。没有原作源代码，只有编译好的程序（"只有机器，没有图纸"）。
- 做法：读懂原程序的一段规则 → 用新代码重写 → 让原版（在模拟器里运行）和新版同时玩同一局，逐步比对必须完全一致 → 再故意把新代码改坏，确认检验能发现（发现不了的写进记录）。
- 已完成的部分（按游戏流程）：连线打怪的战斗规则、盾牌 / 武器 / 吸血；敌人回合的攻击；回合结束时 20 种敌人技能、中毒燃烧回血、死亡与结算；新开一局、每一帧的处理顺序、手指操作。
- 最近两天把这些"零件"组装成完整的"游戏引擎"（recovered_session），从新开局一直打到游戏结束，与原版对照一万三千多个画面全部一致；还发现并修正了原版"游戏结束"画面会顺手记一个结束标记的细节。
- 还缺：技能系统（40 种主动技能，符文玩法依赖它）、装备随机属性、升级菜单、手机界面（高清、多语言、教程）、存档（用户要求暂缓）。

### 用户问：这是逆向吗？为什么别人快、我们慢？用什么技术？能在哪些平台运行？

- 是逆向工程。别人快通常是因为目标不同：改包破解（改几个数）、模拟器运行原程序（仍是旧程序）、照着玩法仿制（细节对不上）。我们要做的是"规则与原版完全相同的全新程序"，每块都要逐步证明一致，所以慢；严格程度可以在界面、动画部分放宽，规则部分建议保持严格。
- 技术：原版是老 iPhone 的 ARM 32 位程序；用反汇编阅读，用 Unicorn 模拟器运行原版片段取得标准答案；新的规则核心用 C++ 写；对照检验用 Python 写（只在开发时用，不进游戏）。
- 平台：C++ 规则核心与设备无关，已能编译出 iPhone 与 Mac 版本；安卓、Windows、网页理论上可移植，尚未试过。"大脑通用，外观按平台做"。

### 用户问：别人用的 Flutter 是什么？

- Flutter 是谷歌做 App 界面的工具（Dart 语言），一套代码出多个平台。它只解决"前端（外观）"，不负责还原规则；别人用它做这类游戏多是照着玩法仿制。
- 现在的工作仍在"大脑"阶段（约八成），前端还没开始。会话库就是给前端准备的接口：前端每帧把手指位置交给大脑，大脑把要显示的东西交回去。

### 用户问：将来肯定全平台，推荐什么？

Claude 的推荐（用户强调这类推荐很重要，须保留）：**界面层用 Godot，备选 Flutter。**

推荐理由（向用户说明的原意）：
1. Godot 是专门做游戏的免费工具（游戏引擎，和 Unity 同类但更轻巧）：动画、特效、粒子、音效、适配各种屏幕都是现成的；本游戏有很多飞行的金币、伤害数字、闪光、碎盾动画，用它更顺手。Flutter 本来是做普通 App 的，做游戏要额外加插件。
2. 全平台：iPhone、安卓、Windows、Mac、Linux、网页，同一套项目导出。
3. 完全免费、开源，没有授权费和收入抽成；Unity 前几年改过收费规则，Godot 没有这个风险。
4. Godot 本身是 C++ 写的，可以把我们的 C++ 规则核心直接装进去，不需要中间翻译。
5. 轻巧，2D 棋盘游戏不显笨重，安装包小。

什么时候改选 Flutter：如果产品更像一个 App（很多普通页面、账号、设置、商城列表，游戏只是其中一部分）。Dungeon Raid 主体是棋盘游戏，所以倾向 Godot。只做苹果设备时，苹果自家 SwiftUI / SpriteKit 体验最好，但以后做安卓要重写界面。Unity 功能最强，但对这种 2D 游戏偏重。

两点说明：用户不需要学这些工具（AI 写，用户看效果、提意见）；规则核心与界面分离，选哪个工具都不浪费已完成的规则还原。

建议的下一步（用户回复"行"，同意）：先用 Godot 做一个简单的试玩原型——接上现有大脑，能看到棋盘、用鼠标或手指连线、打怪、打到游戏结束，画面先用简单方块和数字；用户在电脑上亲手试玩，确认手感和工具顺手后，再补技能、装备，最后做精美画面和手机版本。正式决定见 docs/DECISIONS.md 2026-10-20「前端选型」。

### 其他推荐与说明（同日）

- 严格程度：规则部分（伤害、概率、敌人行为）继续逐项与原版对照；界面、动画可以放宽为"看起来对"，以加快进度。
- 两种推进方式中推荐"先做简单前端试玩，再补完大脑"，好处是用户能更早亲手玩、更早发现手感问题。

### 用户的方向（原话要点）

1. 能做出来，肯定是全平台，iOS 优先，安卓、PC 往后但是肯定要做。
2. 画面要高清化，要多语言，要有教程，相当于原版我们先完善。

4. 新的技能、职业都再往后放。
5. 这些对话也要记在项目里，Codex 可以接手。
